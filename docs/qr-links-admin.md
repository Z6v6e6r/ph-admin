# Постоянные QR-ссылки в ЦУП

## Что реализовано

В ЦУП добавлен раздел «QR-коды»: постоянные короткие ссылки вида
`https://padlhub.su/q/<code>` с изменяемым назначением и счётчиком переходов.

Возможности:

- создание QR-кода: название, станция из существующего справочника,
  место размещения, описание, HTTPS-адрес назначения, статус;
- постоянный код и короткая ссылка, которые не меняются при редактировании;
- смена адреса назначения, названия, станции, места и статуса без перепечатки
  уже наклеенных QR;
- скачивание PNG (1024×1024, чёрный на белом, тихая зона 4 модуля) и SVG;
- копирование короткой ссылки;
- статистика переходов за всё время и за период, таблица по дням, последний
  учтённый переход, история изменений из существующего журнала аудита;
- пауза, включение и архивирование без физического удаления записи и
  статистики; архивный код никогда не выдаётся повторно;
- серверная фильтрация, пагинация и сортировка, учитываемая в верхних
  показателях;
- настройка дополнительных разрешённых доменов для целевых страниц прямо в ЦУП
  (кнопка «Домены») с записью изменений в аудит.

QR кодирует **только** постоянную короткую ссылку. В изображении нет текущего
адреса назначения, персональных данных, токенов и временных кодов.

QR-код не подтверждает резидентство и не даёт прав на инвентарь. Модуль лишь
управляет публичным перенаправлением; чтобы направить постоянный QR на страницу
резидентства, достаточно изменить адрес назначения.

## Маршруты

Публичный origin берётся из доверенной конфигурации
(`QR_LINKS_PUBLIC_BASE_URL`, по умолчанию `https://padlhub.su`), а не из
заголовка Host входящего запроса.

| Назначение | Публичный маршрут | Маршрут backend |
| --- | --- | --- |
| Список QR | `/api/ui/admin?section=qr-links` | HTML ЦУП |
| Карточка QR | `/admin/qr/:id` (alias после патча nginx) | `/api/ui/admin?section=qr-links&qrId=:id` |
| Публичная ссылка | `/q/:code` | `/api/q/:code` (GET и HEAD) |
| Список и показатели | — | `GET /api/v1/admin/qr-links` |
| Создание | — | `POST /api/v1/admin/qr-links` |
| Карточка | — | `GET /api/v1/admin/qr-links/:id` |
| Изменение | — | `PATCH /api/v1/admin/qr-links/:id` |
| Статистика | — | `GET /api/v1/admin/qr-links/:id/stats` |
| История изменений | — | `GET /api/v1/admin/qr-links/:id/history` |
| PNG/SVG | — | `GET /api/v1/admin/qr-links/:id/image?format=png|svg` |
| Справочник станций | — | `GET /api/v1/admin/qr-links/stations` |
| Разрешённые домены: чтение | — | `GET /api/v1/admin/qr-links/allowed-hosts` |
| Разрешённые домены: изменение | — | `PUT /api/v1/admin/qr-links/allowed-hosts` |

Публичный маршрут `/q/:code` не требует входа. Он попадает в backend через
отдельный nginx location (см. ниже), минуя авторизацию ЦУП и без SPA fallback.

## Семантика счётчика

В интерфейсе используется термин «Переходы».

Считаются обработанные GET-запросы к активной короткой ссылке, для которых
backend выполняет HTTP 302. Повторные открытия учитываются. Показатель не
подтверждает загрузку целевой страницы.

Не считаются: HEAD/OPTIONS; неизвестные, приостановленные и архивные коды;
открытие карточки в ЦУП; скачивание QR; переход по кнопке «Открыть целевой
адрес»; явно распознанные prefetch-запросы и известные боты предпросмотра.
Полное исключение всех ботов не гарантируется, физический факт сканирования
камерой не определяется.

Персональные данные не сохраняются: нет IP, полного User-Agent, телефонов,
аккаунтов и cookies аналитики.

## Хранение и индексы

Используется действующая MongoDB ЦУП (новых БД и сервисов нет).

Коллекции (имена настраиваются):

- `cup_qr_links` — `QR_LINKS_COLLECTION`;
- `cup_qr_daily_stats` — `QR_LINKS_DAILY_STATS_COLLECTION`;
- `cup_qr_settings` — `QR_LINKS_SETTINGS_COLLECTION` (дополнительные домены).

Запись QR: `id`, `code`, `name`, `stationId`, `stationName`, `placement`,
`description`, `targetUrl`, `status` (ACTIVE/PAUSED/ARCHIVED), `version`,
`createdBy`, `updatedBy`, `createdAt`, `updatedAt`, `archivedAt`,
`idempotency`.

Дневной агрегат: `qrId`, `dateKey` (YYYY-MM-DD в бизнес-часовом поясе
Europe/Moscow), `redirectsCount`, `lastRedirectAt`, `updatedAt`.

Обязательные индексы:

- `qr_link_id_unique` — `{ id: 1 }`, unique;
- `qr_link_code_unique` — `{ code: 1 }`, unique;
- `qr_link_idempotency_unique` — `{ 'idempotency.actorId': 1, 'idempotency.key': 1 }`,
  unique, sparse;
- `qr_link_status_created` — `{ status: 1, createdAt: -1 }`;
- `qr_link_station_status_created` — `{ stationId: 1, status: 1, createdAt: -1 }`;
- `qr_link_updated_at` — `{ updatedAt: -1 }`;
- `qr_daily_unique` — `{ qrId: 1, dateKey: 1 }`, unique;
- `qr_daily_date` — `{ dateKey: 1 }`;
- `qr_settings_key_unique` — `{ key: 1 }`, unique.

Счётчик увеличивается атомарно одним `updateOne` с `$inc` и `$max` по
документу `(qrId, dateKey)`; уникальный индекс защищает от двойного агрегата.
Сумма за всё время и последний переход вычисляются из этих же агрегатов, поэтому
отдельных расходящихся счётчиков нет. Изменение адреса или статуса статистику не
обнуляет.

Если запись статистики не удалась или превысила таймаут
(`QR_LINKS_STATS_WRITE_TIMEOUT_MS`, по умолчанию 750 мс), разрешённый редирект
всё равно выполняется; в лог пишется `QR_REDIRECT_STATS_WRITE_FAILED` /
`QR_REDIRECT_STATS_WRITE_TIMEOUT`, и переход не объявляется гарантированно
учтённым.

## Права доступа

Добавлены два permission:

- `qr:read` — просмотр списка, карточки, статистики, истории и изображения;
- `qr:manage` — создание, изменение назначения, пауза и архивирование.

Новых прав ролям автоматически не выдаётся. Суперадмин получает их через
существующее правило `['*']`; остальным ролям `qr:read` / `qr:manage`
назначает администратор в разделе «Роли и права доступа».

Изменение списка разрешённых доменов (кнопка «Домены») требует одновременно
`qr:manage` и существующего права `settings:write` и доступно только сотруднику
с глобальным доступом (без ограничения по станциям). Изменения записываются в
аудит. Домены из `QR_LINKS_ALLOWED_TARGET_HOSTS` разрешены всегда; добавленные
в ЦУП домены не могут их отменить.

Ограничение по станциям действует как для остальных прав: пустой список станций
означает все станции, иначе сотрудник видит и изменяет только QR своих станций.
Общий QR без станции доступен только сотруднику с глобальным доступом.

## Конфигурация

```text
QR_LINKS_ENABLED=false
QR_LINKS_PUBLIC_BASE_URL=https://padlhub.su
QR_LINKS_ALLOWED_TARGET_HOSTS=padlhub.su,www.padlhub.su,padlhub.ru,www.padlhub.ru
QR_LINKS_ALLOWED_TARGET_PORTS=443
QR_LINKS_ADMIN_ORIGINS=https://padlhub.su
QR_LINKS_MONGODB_URI=          # fallback: MONGODB_URI
QR_LINKS_MONGODB_DB=           # fallback: MONGODB_DB
QR_LINKS_COLLECTION=cup_qr_links
QR_LINKS_DAILY_STATS_COLLECTION=cup_qr_daily_stats
QR_LINKS_SETTINGS_COLLECTION=cup_qr_settings
QR_LINKS_STATS_WRITE_TIMEOUT_MS=750
QR_LINKS_ALLOWED_HOSTS_CACHE_TTL_MS=5000
# Необязательно: дополнительные собственные хосты, где /q/* уже управляется.
QR_LINKS_SELF_HOSTS=
```

Домены назначения сравниваются точно по hostname с границей метки; поддомены
разрешаются только явной записью в списке (либо явной маской `*.example.com`
в конфигурации). Дополнительные домены добавляются в ЦУП на странице «QR-коды»
кнопкой «Домены»; они кэшируются на короткий TTL
(`QR_LINKS_ALLOWED_HOSTS_CACHE_TTL_MS`). Удаление домена запрещает новые ссылки
на него, но не ломает уже напечатанные QR: сохранённый адрес перепроверяется по
структурным правилам без повторного применения изменяемого allowlist. Разрешён только абсолютный HTTPS URL, порт 443 по умолчанию;
запрещены userinfo, CRLF и управляющие символы, `javascript:`/`data:`/`file:`,
protocol-relative URL, localhost/loopback/private IP и переходы на собственные
`/q/*`. Query-параметры сохранённого адреса сохраняются; публичные
`?url=`, `?next=`, `?redirect=` на назначение не влияют.

## Подключение

1. Собрать и раскатать образ обычным процессом выпуска. Приложение не создаёт
   индексы в production: при `QR_LINKS_ENABLED=true` отсутствие нужных индексов
   останавливает готовность (как у остальных Mongo-модулей).
2. Проверить и применить аддитивные индексы отдельным согласованным действием:

   ```bash
   npm run qr-links:indexes:check
   QR_LINKS_INDEX_APPLY=CONFIRM npm run qr-links:indexes:apply
   npm run qr-links:indexes:check
   ```

3. Добавить nginx-блоки из
   `deploy/server-147/nginx-qr-links-location.conf` в существующий HTTPS
   `server {}` рядом с `/api/`. Патч не применяется автоматически:

   ```bash
   sudo nginx -t
   sudo systemctl reload nginx
   ```

   Дополнительно можно включить ограничение частоты: файл
   `deploy/server-147/nginx-qr-links-rate-limit-http.conf` подключается в
   `http {}`, после чего в location `/q/` раскомментируется
   `limit_req zone=qr_public burst=20 nodelay;`. Это не применяется
   автоматически.

   Для контейнерной конфигурации те же маршруты добавлены в
   `deploy/nginx/ph-ab.conf`. Если перед приложением есть CDN, отключите
   кэширование `/q/*` (или исключите путь из кэша). Дополнительно можно
   ограничить частоту на уровне nginx: зона `limit_req_zone` объявляется в
   `http {}`, а `limit_req zone=... burst=... nodelay;` — в location `/q/`.
4. Задать переменные окружения и включить модуль: `QR_LINKS_ENABLED=true`,
   затем перезапустить сервис штатным способом.
5. Выдать `qr:read` / `qr:manage` нужным ролям в ЦУП. До выдачи раздел
   показывает состояние «нет прав».

## Проверка после релиза

```bash
# Публичный редирект и заголовки
curl -sS -o /dev/null -D - https://padlhub.su/q/<code> | grep -Ei 'HTTP/|location|cache-control|x-robots-tag'

# Неизвестный код
curl -sS -o /dev/null -w '%{http_code}\n' https://padlhub.su/q/unknown123

# Статусы без кэша: пауза = 200 с текстом, архив = 410, сбой = 503
# API требует авторизацию
curl -sS -o /dev/null -w '%{http_code}\n' https://padlhub.su/api/v1/admin/qr-links
```

Ручной smoke-сценарий: создать QR → скопировать ссылку → скачать PNG и SVG →
открыть короткую ссылку и убедиться в 302 на сохранённый адрес → увидеть рост
счётчика → изменить адрес назначения → проверить ту же короткую ссылку →
приостановить и проверить нейтральную страницу → включить → архивировать и
проверить 410.

Локально модуль проверяется так:

```bash
npm run test:qr-links
npx tsc -p tsconfig.build.json --noEmit --incremental false
npm run build
```

Gated Mongo-проверка (только одноразовая БД, никогда production):

```bash
QR_LINKS_TEST_MONGODB_URI=mongodb://127.0.0.1:27017 \
QR_LINKS_TEST_MONGODB_DB=qr_links_test \
npx ts-node test/qr-links.mongodb.test.ts
```

## Откат

1. Выключить `QR_LINKS_ENABLED` и вернуть предыдущий образ приложения.
2. Не удалять коллекции и индексы: они аддитивны и не влияют на старый runtime.
3. При откате nginx убрать блоки `/q/` и `/admin/qr` (тогда `/q/*` вернёт
   404) либо оставить их: при выключенном модуле `/q/*` отвечает 503 без
   выдуманного назначения.
4. Сохранить коды, периоды и результаты read-back для разбора. Удаление данных —
   только отдельным reviewed repair после backup и dry-run.

## Ограничения

- Счётчик не доказывает сканирование камерой и не исключает всех ботов.
- «Уникальные посетители» и fingerprinting не реализованы намеренно.
- Бизнес-часовой пояс — Europe/Moscow; другие пояса не поддерживаются.
- История в карточке показывает последние 100 записей существующего аудита.
- Справочник станций — существующие настройки станций ЦУП. Для QR также доступна
  станция «Завидово» (`Zavidovo`), даже если она ещё не заведена в настройках
  мессенджера; существующая настройка станции имеет приоритет. Если справочник пуст,
  сотруднику с ограничением по станциям доступны его stationId.
- Красивые адреса `/admin/qr` и `/admin/qr/:id` работают только после
  применения nginx-патча; без него используется
  `/api/ui/admin?section=qr-links`.
- Раздел не создаёт и не проверяет резидентство, инвентарь, платежи, Viva и
  абонементы.

# Уровень только в ЦУП

Новый игрок не имеет уровня. Первое назначение — собственный онбординг ЛК либо
уполномоченный администратор/тренер ЦУП. Default D/1.0 и bootstrap уровня из Viva
не используются. Viva остаётся источником идентичности и контактов.

`POST /admin/player-ratings/assignments` требует `player-ratings:write`, точный clientId,
число 1–7 (до пяти знаков), непустую причину от 10 символов и idempotencyKey.
Клиент подтверждается по фактическому ID ответа Viva; level custom fields не читаются.
Транзакция вставляет immutable `RATING_INITIAL_ASSIGNED`, каноническое состояние,
compatibility projection и при включённой интеграции outbox для ЛК2. Конфликт имеющегося
состояния, client/phone-key history или aliases не перезаписывается первым назначением.
Idempotency key связан с актором, игроком и payload. Действующая CAS-корректировка
остаётся отдельной операцией.

Поиск кандидатов возвращает только необходимые идентификационные поля. Раздел уровней
позволяет выбрать клиента из этого поиска и назначить первый уровень с причиной.
Права read/write проверяются явными permission decorators. Новых прав по умолчанию и
роли тренера автоматически не создаётся; нужный аккаунт получает существующие
`player-ratings:read` и `player-ratings:write` через управляемую роль отдельной операцией.

Viva outbox больше не создаётся. `projection.status` возвращает `NOT_REQUIRED`.
Старый `/projection/retry` отвечает конфликтом `VIVA_LEVEL_PROJECTION_RETIRED`, не
перезапускает очередь. Исторические provider rows сохранены. Методы интеграции чтения
и записи Viva-level fail-closed. Совместимость enum статуса расширена, UI обновлён.

CUP→PadlHub/LK2 — отдельная действующая проекция. Первое назначение в immediate outbox
и background reconciliation отображается в существующий wire event type
`RATING_MANUALLY_CHANGED`; transport contract получателя не расширяется. Обычные
изменения продолжают использовать канонический lastEventId/CAS.

Парный LK PR должен перевести frontend, Node-RED, FPR helper и rating workers, включая
старые retry paths. Полный план: `docs/CUP_ONLY_PLAYER_LEVEL_CUTOVER.md` в репозитории LK.
Для живого переключения нужны backup/restore rehearsal, сверка всех существующих
уровней и идентичностей, уникальные индексы и остановка старых level senders. Физическое
удаление Viva fields не выполняется кодом и требует отдельного разрешения.

Проверки: `npm run test:player-ratings`, `npm run test:auth-rbac`, `npm run build`.
Изменённые endpoints и DTO не являются доказательством live deployment. После первого
canonical-only изменения откат к старому Viva UI без reconciliation небезопасен.

## Совместимость с турнирным владельцем

CUP отправляет вычисленные изменения уровня из того же канонического состояния.
Проекция переносит идентификатор события и монотонную ревизию. Для первичного
назначения сохранён прежний wire type, чтобы повтор ранее доставленного события
оставался идемпотентным. LK2 с расширенным ingress разворачивается до готовности
отправителя новых типов. При задержке действует последняя доставленная проекция
для отображения, а допуск проверяет актуальное состояние CUP.

Сборка исторического recovery сохраняет исходный SDK и строгий список файлов.
В качестве кандидата допускается точный хеш SDK с #119. Дополнительная проверка
первого назначения запускается в CI отдельной командой, что сохраняет байты
`package.json` в историческом recovery closure.

Восстановление после канонических назначений сохраняет актуальный backend, уровень
и очередь LK2. `TOURNAMENT_OWNER_RECOVERY_ONLY=true` у CUP и нового router закрывает
новые операции, сохраняя обработчики начатых. Исторические медиа/MAX recovery
предназначены для своей области и не заменяют этот backend и канонических readers.

## Ограниченный пилот уровня в ЛК2

Для пилота задайте `PADLHUB_PLAYER_LEVEL_PROJECTION_MODE=pilot` и
`PADLHUB_PLAYER_LEVEL_PROJECTION_PILOT_BINDINGS` в виде JSON-массива точных пар
`{"playerKey":"client:synthetic-player","clientId":"synthetic-player"}`. Источник пар —
текущий канон ЦУП и подтверждённая активная привязка `VIVA/viva_profile` выбранного tenant ЛК2.
Нужны от одной до 100 уникальных пар. Не используйте aliases или значения, выведенные из
телефона. Ошибка режима, пустой список и неверные пары останавливают запуск. Отсутствие
режима и списка сохраняет прежний режим полного отправителя.

Пилот ограничивает сверку, новый outbox, захват просроченных lease и ручной retry.
До отправки событие, значение, буква и ревизия повторно сверяются с каноном. Уже существующая
строка другого clientId под тем же playerKey сохраняется и учитывается в
`pilotBindingConflicts`. Смена привязки требует отдельной сверки этого случая.
Ответ ЛК2 `409 CUP_PLAYER_LEVEL_ACTOR_NOT_MAPPED` переводит конкретную запись в
`WAITING_FOR_MAPPING`. Попытка не расходует лимит доставки и не открывает общий circuit.
Через пять минут запись можно проверить повторно. После подтверждения связи доступен ручной
retry того же события и ревизии. Другие 409 сохраняют обычный контракт ошибок.

При паузе выключайте `PADLHUB_PLAYER_LEVEL_PROJECTION_ENABLED`, сохраняя режим пилота и список
для ограничения ручного retry. Не переводите в полный режим, пока не подтверждено ожидаемое
покрытие. При несовпадении активного графа, чужой привязке, росте ошибки или неоднозначном ACK
сохраните журнал, состояния и очереди до сверки. Порядок паузы проекции — sender, затем ingress.

## Коррекция буквы с нулевой дельтой

Существующий `POST /admin/player-ratings/:playerKey/changes` принимает одновременно
`expectedPreviousGrade` и `expectedClientId` для отдельного режима проверки буквы.
Применение требует неизменных текущих clientId, последнего eventId, числа и прежней буквы.
Запрашиваемое число должно точно совпасть с сохранённым. Транзакция добавляет событие
с фактической прежней буквой и нулевой дельтой, обновляет канон и compatibility.
Попытка другого предшественника с тем же ключом возвращает конфликт. Точный повтор тем же
актором возвращает исходное событие. При paused sender запись в Viva или LK2 не ставится.

Подготовленный для согласования пакет храните приватно. Перед будущим применением сверяйте
каждый исходный снимок, проверяйте нулевую дельту в ответе и в журнале. При первом необъяснённом
конфликте сверяйте префикс уже подтверждённых операций по исходным ключам и остановите оставшиеся.
Исторические события сохраняются, а repair с прежней формулой и legacy Viva outbox исключается
из процедуры. Изменение данных, включение флагов, миграция ЛК2 и установка артефактов требуют
отдельного разрешения.

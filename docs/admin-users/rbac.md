# Роли, сотрудники и аудит ЦУП

ЦУП хранит сотрудников в MongoDB `admin_users`, роли — в `admin_roles`, а журнал действий — в `admin_audit_log`. `ADMIN_AUTH_USERS_JSON` остаётся только начальным способом загрузить первого суперадмина: после первой инициализации источником истины становится MongoDB.

Роль задаёт доступ к разделу и действию: `dialogs`, `games`, `tournaments`, настройки, сотрудники, роли и аудит. Пустой список станций означает все станции; если станции указаны у роли и сотрудника одновременно, сервер использует их пересечение. При нескольких ролях это пересечение считается отдельно для каждого права: доступ «читать игры» на одной станции не даёт «изменять игры» на другой. Коннекторы аналогично ограничиваются записью сотрудника.

Все проверки выполняются по текущей записи сотрудника на сервере, а не по скрытым кнопкам в браузере. Поэтому изменение роли или выключение учётной записи начинает действовать сразу, в том числе для уже выданных токенов. Пароли, созданные или изменённые через ЦУП, сохраняются как scrypt-хэши; API никогда не возвращает пароль.

В «Настройки → Админы и управляющие» суперадмин может создавать и менять сотрудников, роли, права, станции и коннекторы. Журнал показывает входы, изменения сотрудников и ролей, а также успешные серверные изменения ресурсов. Удалить последнего активного суперадмина или системную роль нельзя.

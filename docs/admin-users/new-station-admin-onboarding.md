# Администраторы новых станций

После выпуска station mappings ЦУП автоматически добавит новые станции в
`Настройки -> Станции`. Учётные записи не создаются автоматически: для каждого
человека суперадминистратор создаёт отдельного сотрудника в
`Настройки -> Админы и управляющие`, чтобы пароль не попадал в Git, чат, shell
history или deploy-артефакты.

| Станция | Station scope в ЦУП | Callback бота |
| --- | --- | --- |
| Питер | `Piter` | `piter` |
| Котельники | `Kotelniki` | `kotelniki` |
| Щербинка | `Shcherbinka` | `shcherbinka` |
| Люберцы | `Lyubertsy` | `lyubertsy` |
| Коломна | `Kolomna` | `kolomna` |

Для создания учётной записи нужны: отображаемое имя, уникальный латинский
логин, пароль длиной не менее 10 символов и одна station scope из таблицы.
Роль — `STATION_ADMIN`. Для работы с текущими диалогами используются
коннекторы `MAX_BOT` и `LK_WEB_MESSENGER`; добавлять другие коннекторы нужно
только по отдельной бизнес-потребности.

## Приёмочные проверки для каждой учётной записи

1. Новый администратор входит в ЦУП и видит в профиле только назначенную
   station scope.
2. В разделе диалогов видны обращения своей станции из MAX и веб-мессенджера.
3. Прямой запрос диалога другой станции возвращает отказ и не раскрывает его
   метаданные.
4. Ответ в своём диалоге попадает в outbox нужного коннектора; локальная запись
   или mock не считается доказательством доставки клиенту.
5. После блокировки учётной записи повторный вход и использование старой сессии
   отклоняются.

Активация карточки станции для публичного создания игр — отдельный контур. Она
не должна расширять права администратора и не должна выполняться вместе с
созданием учётной записи.

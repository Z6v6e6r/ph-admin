# Контракт экрана «Диспетчерская дня»

Статус: `DRAFT_FOR_REVIEW`

## 1. Задача экрана

За 5–10 секунд оператор должен ответить:

1. какие ресурсы заняты;
2. что начнётся в ближайшее время;
3. где есть проблема;
4. какое действие нужно выполнить;
5. актуальны ли данные.

Экран не должен требовать изучения цветовой легенды для понимания оплаты, заполненности и ошибок.

## 2. Компоновка desktop

### Глобальный уровень ЦУП

Сохраняется существующая навигация ЦУП. Внутри рабочего полотна расписанию отдаётся максимальная ширина; отдельный постоянный мини-календарь слева не вводится.

### Строка управления

Слева направо:

- станция;
- дата, назад/вперёд, `Сегодня`;
- режим `День | Лента | Загрузка`;
- ось `Корты | Тренеры | Зоны`;
- поиск `Найти время`;
- действие `Создать`;
- индикатор актуальности.

Вторая строка:

- быстрые фильтры;
- `Только проблемы`;
- масштаб;
- `Скрыть нерабочие часы`;
- сохранённый вид пользователя.

### Сводка

Компактная полоса над сеткой:

`Загрузка 72% · 5 окон · 3 требуют оплаты · 2 недобора · 1 сбой синхронизации`

Клик по показателю применяет фильтр и не уводит со страницы.

### Сетка

- время вертикально;
- ресурсы горизонтально;
- шапка ресурсов закреплена;
- шкала времени закреплена;
- текущая линия времени видна только для сегодняшней даты;
- горизонтальная и вертикальная виртуализация;
- минимум 160 px на колонку в комфортной плотности;
- нерабочее время визуально приглушено;
- техническое закрытие штрихуется;
- drag preview показывает новый интервал, ресурс и конфликт до отпускания.

Заголовок ресурса может показывать рабочее состояние, следующий свободный продаваемый интервал и активное закрытие. Визуально пустой интервал не помечается доступным без sellable option.

При большом количестве кортов используются группы ресурсов и виртуализация, а не уменьшение карточек до нечитаемого размера.

## 3. Карточка occurrence

### Визуальная семантика

| Измерение | Представление |
|---|---|
| Тип | спокойный цвет фона/полоса и текстовый тип |
| Lifecycle | текстовый badge или иконка |
| Оплата | отдельный индикатор суммы/доли |
| Вместимость | `3/4`, слоты или короткая группа аватаров |
| Проблема | красный warning + короткий текст |
| Источник | небольшой `Viva`, `ЦУП`, `API` |
| Sync | отдельный индикатор только при pending/problem |

Красный не используется как обычный цвет персональной записи.

### Адаптивная плотность

До 30 минут:

```text
16:00  Персональная
⚠ 1 200 ₽ к оплате
```

30–60 минут:

```text
16:00–17:00             1/1
Персональная · Анна
Тренер: Павел     ⚠ оплата
```

Более 60 минут:

```text
16:00–17:30             3/4
Открытая игра 2×2
Иван + 2 игрока
D+2–C2 · 2/3 оплатили
```

При уменьшении высоты скрываются вторичные строки, но время, тип и проблема остаются.

## 4. Правая панель

Открывается без ухода со страницы и остаётся при переключении между событиями.

Шапка:

- тип и название;
- дата, время, длительность;
- ресурсы;
- lifecycle и sync state;
- версия/признак чужого изменения.

Вкладки:

- `Основное`;
- `Участники`;
- `Оплата`;
- `Waitlist`;
- `Публикация`;
- `Сообщения`;
- `История`.

Постоянная зона действий:

- основное действие по текущему состоянию;
- `Перенести`;
- `Дублировать`;
- `Отменить`;
- меню редких/опасных действий.

Вкладка не должна терять несохранённый ввод без предупреждения.

## 5. Создание

Клик по свободному месту открывает компактный выбор типа. Протягивание сразу заполняет время и ресурс.

Форма строится по progressive disclosure:

1. тип, время и ресурс;
2. клиенты/участники;
3. тренер и дополнительные ресурсы;
4. цена/способ оплаты;
5. публикация;
6. дополнительные правила.

Для частой аренды корта оператор может подтвердить первые два шага с клавиатуры. Для игры, серии или турнира показываются необходимые секции.

Если оператор создаёт запись от имени клиента, панель явно показывает:

- исполнитель команды;
- клиент-получатель;
- организатор;
- участники/гости;
- плательщики.

Эти роли не схлопываются в одно поле `клиент`.

## 6. Preview переноса

После drag/drop или редактирования система показывает только значимые последствия:

```text
Перенос: 16:00–17:30, Корт 3 → 18:00–19:30, Корт 4
Цена: 2 400 ₽ → 3 200 ₽
Будут уведомлены: 4 игрока и тренер
⚠ Один игрок не подходит под правило прайм-тайма

[Вернуть] [Подтвердить перенос]
```

При hard conflict кнопки подтверждения нет. Вместо неё показываются 2–3 серверные альтернативы.

Override показывается только пользователю с правом `schedule:override`, требует причину и не доступен для resource collision.

Для occurrence серии preview дополнительно требует выбрать:

- `только это` или `это и последующие`;
- сохранить цену или пересчитать допустимые commitments;
- `всё или ничего` либо `только доступные`.

Результат частичной операции открывает отчёт по датам, а не только toast.

## 6.1. Поиск времени

Панель `Найти время` принимает:

- тип активности;
- дату/диапазон;
- длительность;
- клиентский сегмент/membership;
- тренера или требования к нему;
- предпочтительные корты.

Карточка результата:

```text
Сегодня, 18:00–19:30 · Корт 4
3 200 ₽ · Прайм-тайм
Подходит тренер · без пустого окна
[Создать]
```

Если вариантов нет, UI показывает причины и ближайшие альтернативы, а не пустой список.

## 6.2. Waitlist operations

Вкладка показывает:

- режим очереди и cutoff;
- кандидатов и требуемые слоты/команды;
- eligibility;
- активный offer и время до expiry;
- причину skip;
- ручное действие `Предложить`, `Перевести в состав`, `Пропустить`.

Ручное действие использует тот же offer/hold контракт и не может обойти capacity атомарностью браузерной кнопкой.

## 7. Состояния загрузки и ошибок

Сетка различает:

- первоначальную загрузку;
- пустой день;
- нет доступа к станции;
- projection stale;
- live-канал отключён, polling работает;
- частичная ошибка сводки;
- полная недоступность данных;
- sync problem отдельных событий.

Сбой сводки не скрывает сетку. Сбой внешней projection не превращает canonical событие в пустое место.

## 8. Клавиатура и доступность

- карточки доступны по Tab;
- Enter открывает панель;
- стрелки перемещают фокус между событиями;
- создание и перенос имеют клавиатурную альтернативу;
- предупреждения не зависят только от цвета;
- контраст текста и интерактивных состояний соответствует WCAG AA;
- reduce motion отключает анимированный drag/перестроение.

## 9. Mobile/tablet

На телефоне сетка по всем кортам не уменьшается.

Основной режим:

- дата и станция;
- `Сейчас`, `Скоро`, `Проблемы`, `Все`;
- список событий;
- фильтр по ресурсу;
- нижняя карточка события.

На планшете допустима сетка 2–3 выбранных ресурсов с горизонтальной прокруткой.

## 10. Необходимые данные read-модели

Карточка сетки получает одним DTO:

```text
id, version, startAt, endAt, resourceIds
kind, compactTitle
lifecycleStatus
capacity: { occupied, total, waitlist }
payment: { state, paidMinor, dueMinor, currency }
attention: { level, code, label }
publicationSummary
sync: { state, sourceSystem }
participantPreview[]
projectionVersion, asOf
```

Browser DTO не содержит Viva IDs, provider payload, секреты и лишние персональные данные.

Отдельный availability DTO содержит `sellableOptionId`, TTL, resource plan, price quote reference, policy evaluation и reason codes. Он не является резервом ресурса до создания HOLD.

## 11. UX acceptance

- время/тип/проблема читаются на карточке высотой 30 минут;
- смена масштаба не меняет start/end события;
- клик по KPI фильтрует сетку и имеет явный reset;
- при version conflict изменение пользователя не затирает чужую версию;
- перенос через drag и через форму вызывает один командный контракт;
- поиск времени и клиентский booking API возвращают одинаковые policy decisions;
- online capacity и admin reserve визуально различимы в панели, но не раскрывают лишние правила клиенту;
- серия показывает scope и price mode до подтверждения;
- waitlist offer имеет expiry и одного победителя;
- закрытие правой панели не меняет данные без команды сохранения;
- снятие публикации визуально не выглядит как отмена;
- screen reader получает текстовое описание типа, времени, ресурса, оплаты и проблемы.
